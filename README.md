## Verified operator: capacity watcher
Requires **Python 3.10+**; no account, network, scheduling, file deletion, or write access. It sums apparent sizes of ordinary files in configured folders; it does **not** measure disk free space or physical disk allocation.

```bash
python -m unittest discover -s tests -v
python scripts/capacity_watch.py --config config/examples/capacity-watch.example.json
```

The sample uses a synthetic directory. Keep any configuration with real paths **outside this repository**. Failed scans are errors, not zero-byte results. Independent verification was [reported and recorded](docs/verification/capacity-watch-2026-11-17.md) for commit e573312; the full kit remains PREVIEW, not RELEASED.

**VERIFIED with limitations: Shared Intake / 共通受け皿 (commit d9b24aa).** A local collector that accepts JSON items from multiple producers, persists append-only daily JSONL event journals, maintains one derived unprocessed-count flag, and records state changes. It does **not** judge meaning, connect to services, auto-deliver, schedule work, or delete data. [Technical spec](docs/operators/shared-intake.md), [HowTo](docs/howto/shared-intake.md), [beginner explanation](docs/explain/shared-intake.md), [P1 decisions](docs/plans/shared-intake-p1.md), [local test report](docs/verification/shared-intake-local-2026-11-17.md) and [reported independent verification](docs/verification/shared-intake-independent-2026-11-17.md). **VERIFIED within tested limits: Injection-size watcher / 投入量見張り係 (commit a60df96).** Measures explicit always-loaded AI context files in exact bytes, records measurements in a separate private directory and checks configured per-file size and seven-day-derived growth thresholds. Only upon a warning does it create **private dated backups and conservative draft proposals**, plus actual byte comparisons and mechanical self-tests. Markdown/text drafts remain byte-identical; JSON draft compaction only removes insignificant whitespace. **No source edits, no application, no model-token claim, no scheduler.** Semantic/key-point reconstruction is `NOT_ASSESSABLE`, not PASS. See [HowTo](docs/howto/injection-size-watch.md), [technical contract](docs/operators/injection-size-watch.md), [beginner explanation](docs/explain/injection-size-watch.md), [P1 decision](docs/plans/injection-size-watch-p1.md), [local test evidence](docs/verification/injection-size-watch-local-2026-11-17.md), [reported independent validation](docs/verification/injection-size-watch-independent-2026-11-17.md). Whole-kit 168/168 reported PASS under Linux/root; direct external CLI proof for the weekly-growth exact 10% boundary is still UNVERIFIED. Other OSs and non-root permissions UNVERIFIED.

**VERIFIED within tested scope: Organizer / 整理係 (commit 84ca9fe).** Despite the name, this is **not** a folder sorter. It proposes tag-based **file lifetime** decisions using root-local `.retention_records.json` entries and each listed file's modification time. `disposable` + at least the configured duration (sample: 14 days) is a **candidate only**. `permanent` is never a candidate, and unregistered files are not examined. Missing, invalid, linked or unknown records are held or fail explicitly. The CLI never moves, writes, tags, trashes or purges anything. [Technical contract](docs/operators/organizer.md), [HowTo](docs/howto/organizer.md), [beginner explanation](docs/explain/organizer.md), [P1 decisions](docs/plans/organizer-p1.md), [local tests](docs/verification/organizer-local-2026-11-17.md), [reported independent verification](docs/verification/organizer-independent-2026-11-17.md). Whole-kit 223/223 tests and C-7 explanation PASS were independently reported for Linux/root. Non-root, Windows and other filesystems are UNVERIFIED.

**VERIFIED within tested limits: Deadline reminder / 期限リマインダー係 (deae596).** Local one-shot deadline register/reschedule/cancel/check with strict UTC + IANA local + epoch-second validation, stable idempotent fire IDs and a durable **private outbox**. An append-only journal can recover a missing derived outbox; a separate failure ledger groups repeated errors and distinguishes a later recurrence. **No network delivery, no shared-intake integration, no schedule/cron, no message reading or human acknowledgment guarantee.** The manual `ack` only records an **unverified external receipt assertion** (`consumer_verified=false`); it is not proof of delivery. [Technical contract](docs/operators/deadline-reminder.md), [HowTo](docs/howto/deadline-reminder.md), [beginner explanation](docs/explain/deadline-reminder.md), [P1 decisions](docs/plans/deadline-reminder-p1.md), [local tests](docs/verification/deadline-reminder-local-2026-11-17.md). No real delivery was exercised or implemented. Non-root and other OS behavior remain UNVERIFIED.

**VERIFIED within tested scope: History Cleaner / 履歴掃除係 (commit 61c3364).** Contrary to the name, this is **not** disk-file cleanup or Git history rewriting. It examines **Shared Intake's append-only JSONL v1** and previews age-eligible `reported`/`discarded` records after a configurable 90-day default. Nonterminal items are never candidates; unknown source roles, completed runs, error events and unsupported prune evidence are held/protected. Public Intake v1 does not separate deduplication `seen` from item events and does not support private `prepare/complete` records: **every candidate remains unsafe to delete, and `safe_to_delete_count=0`**. Entire tool is read-only; no `--apply`, no deletion, no event renumbering, no scheduler. [Technical spec](docs/operators/history-cleaner.md), [HowTo](docs/howto/history-cleaner.md), [beginner explanation](docs/explain/history-cleaner.md), [P1 decision](docs/plans/history-cleaner-p1.md), [local verification](docs/verification/history-cleaner-local-2026-11-17.md). Standalone producer tests: **66 PASS + 1 SKIP**; V.E.S.T.A.R.D. subsequently reported [independent fresh-clone testing](docs/verification/history-cleaner-independent-2026-11-17.md) **370/370 PASS with no SKIP**, including the real Shared Intake CLI integration test. C-7 PASS was also reported. Real deletion, independent seen/prune records, non-root and other OS support remain unverified or unimplemented.

**New PILOT: Notion Jobs Collector / Notion案件収集係.** The *private* operator reads Notion as a source; the **public pilot is OFFLINE only**. It accepts synthetic parent+dated-child page responses via a swappable read-only `PageProvider` interface (bundled provider reads **local fixtures only**). It uses strict versioned YAML conditions and a one-time bootstrap baseline; later checks detect added `YYYY/MM/DD` child pages or newly introduced **page-local** job URLs after removing query strings/fragments. Parent read/validation failure is ERROR, child failure is PARTIAL and retried next run. It atomically saves private seen state and **Shared Intake v1-shaped local pending proposals**, but does **NOT** connect to Notion, ingest into the real receiver, send alerts, schedule cron or apply for work. Data is data: page-body instructions are never executed. [Technical spec](docs/operators/notion-jobs-collector.md), [HowTo](docs/howto/notion-jobs-collector.md), [beginner explanation](docs/explain/notion-jobs-collector.md), [P1 decisions](docs/plans/notion-jobs-collector-p1.md), [producer tests](docs/verification/notion-jobs-collector-local-2026-11-17.md).
