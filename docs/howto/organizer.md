# 整理係：初心者向け再現HowTo（PILOT）

## 何をする？

作成者があらかじめ登録した `disposable` / `permanent` と、ファイル更新時刻だけで「**ゴミ箱に移す候補として人間に提示するか**」を判定する。整理係の公開版は**移動も削除もできない**。

## 安全な合成例での実行

Python 3.10以降を使う。次のコマンドは公開リポジトリのルートから実行。

```bash
python -m unittest discover -s tests -v
python scripts/organizer.py --config config/examples/organizer.example.json
```

合成例は `examples/organizer/root` の2つのテキストファイルと `.retention_records.json`。最新のcloneで作ったファイルのmtimeは新しいので、`disposable` が `not_due`、`permanent` が `excluded` となるのが普通。**mtimeはclone環境に依存するため、固定の年齢結果を約束しない**。固定境界はユニットテスト内で合成mtimeを設定して検証している。

`status=candidates` は候補を見つけただけ。`status=partial`（exit1）は未知タグ・欠落などの保留。`status=error`（exit1）は設定・記録等が安全に読めなかった。どちらも「何も見つからなかった」ではない。

## 自分のファイルを対象にするなら

1. **所有者の許可があるローカルルートだけ**選ぶ。実際のルートはJSON設定を**リポジトリ外**に置いて指定する。
2. ルート直下の `.retention_records.json` に、安全な相対パスと登録時の `class` を記入する（このツール自体はタグを付けない）。未登録ファイルは調べない。
3. `age_days`（整数、単位は24時間）を明示設定する。初期サンプルの14日をそのまま実運用判断に使わない。
4. コマンドを手動で実行し、候補・未到来・対象外・保留を確認する。相対パスを含む結果は公開しない。
5. 候補でもゴミ箱移動・削除は**できない**。実操作が必要なら、別系統として本人の明示承認と再検証が必要。

## 失敗時と安全な停止

ファイルが欠落、日時を読めない、タグを知らない、権限がない等なら保留として理由を返す。重複記録・破損JSON・ルート不正等ならエラーで停止。必要なら元の所属記録の管理者が問題を確認する。本係は記録自体を書換えないので、バックアップからの「復旧操作」は発生しない。通常の終了で安全に停止できる。

第3号「付け忘れ検出係」は未タグの**新規**ファイルを見つける別ツール。第6号ではその未タグファイルに後から分類を推測しない。
