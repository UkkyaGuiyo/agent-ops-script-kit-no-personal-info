# 投入量見張り係：技術仕様

**Status: VERIFIED（対象コミット a60df96b17875e0c49f07b5beafa9fd04469b9ee、Linux/root実測範囲）.** 新規cloneで全168/168件のテストPASSとC-7説明再現PASSが検証担当から報告された。週次増加率10%ちょうどのCLI独立実測はUNVERIFIED（制作側単体試験PASS／Decimal実装確認）。非root・他OS・大量ファイル・実運用はUNVERIFIED。正式RELEASEDではない。GPL-3.0-only。Python 3.10+、標準ライブラリのみ。

## 役割
AIの会話で繰り返し読み込まれる、**明示的に指定された常駐コンテキスト用ファイル**の容量（ファイルサイズ）を計測する。日次ログなど必要な時だけ検索する資料は、設定対象に入れない。計測は **bytes (B)** が正本。補助的にUTF-8デコード後のPython文字数（Unicodeコードポイント単位）と`splitlines()`に基づく行数を報告。**モデルtoken数は測らず、バイトから推定もしない。** ディスク使用容量ではなくファイルの論理長。

## 入力・設定

```json
{
  "version": 1,
  "weekly_growth_percent": 10.0,
  "targets": [
    {"name": "synthetic-memory", "path": "../../examples/injection-size/synthetic-memory.md", "limit_bytes": 60000}
  ]
}
```

- `targets` は1件以上。`name` は一意の英数字・`_`・`-`で始まりの文字は英字。`path` は設定ファイル位置からの相対パス、または絶対パス。実際の設定はGitHub外で管理する。
- `limit_bytes` は非負整数B。省略時60,000 B（10進KB）。`weekly_growth_percent` は0〜1000の有限数、各対象共通。例の10%と60,000Bは推奨の普遍値ではない。**超過は厳密な `>`**。
- `.md`, `.txt`, `.json` のみ。UTF-8厳格デコード。JSONは文法と重複キーを検査し、NaN等は拒否。1件あたり最大2,000,000 B（上限を超える場合はエラーで、0 Bや除外とはしない）。シンボリックリンクの経路は拒否。複数別名で同じファイルを指定できない。
- `--state-dir` は利用者が先に作ったローカルディレクトリで、**チェックアウト外、かつ測定対象ファイルを含まない場所**。個人情報や原文があるバックアップはこのディレクトリにのみ作成される。高権限実行は禁止。

## 測定、履歴、警告

- `injection-measurements.json` に測定時刻（UTC）、対象別B数を保存。SHA-256でpayload整合性を検査（**認証ではない**）。`.injection-initialized.json` とhistoryの片方が欠けた場合は異常停止。過去の状態を推測で作り直さない。
- 重複排除は**NONE**。測定は毎回1サンプル追加する。ロック`.injection-size.lock`で多重起動を防止し、競合時はexit 3。停止後の残留ロックは人間が確認して対処する。
- 前回測定値との差分を表示。週次判定には「現在から7日以上古い最後の測定」を使う。7日未満しか無ければ `UNKNOWN_NO_BASELINE` / `UNKNOWN_LESS_THAN_7_DAYS` とし、**未確認の増加率を安全値の0%に置き換えない**。
- 週換算増加率は `[(now_bytes−reference_bytes)/reference_bytes] × 100 × [604800秒/実際の経過秒数]`。時間補正された派生指標で、実測したバイト数やモデルtoken数ではない。元値が0Bで増加した場合は率を数値化せず、超過を立てる。境界は60,000 B **ちょうどでは超過ではない**、増加率10% **ちょうどでも超過ではない**。
- どちらか超過した時だけ `status=warning`。超過なしは`status=ok`。外部へ通知しない。失敗は`status=error`、失敗ファイルは`bytes=null`、**合計もnull**。一部成功しても全件成功とせず、履歴も進めない。

## 自動で作る下書き一式（原本変更禁止）

超過時は状態ディレクトリ内だけに`package-<UTC-date>-<random>/`を作る。作成途中のものは `.injection-temp-*` として残り、次回は明示エラーで停止する。人間が確認するまで自動削除しない。

- `backups/<alias>.<ext>`：オリジナルバイトをそのまま複写してSHA-256で照合。
- `drafts/<alias>.draft.<ext>`：`.json`は**重複キーのないJSONの空白のみを詰める**。元のJSON値を再パースして比較する。既に短いJSONはそのまま。`.md`/`.txt`は意味を推測して削れないため**原文とバイト単位で同じ下書き**を生成。
- `audit.json`：閾値超過の対象、実測/推定の区別、tokens UNKNOWN。
- `classification.json`：公開版独自A〜F（A保持、B形式のみ、C圧縮要レビュー、D必要時参照へ移動要レビュー、E削除要承認、F意味の判断待ち）。公開版の自動候補はA/B/Fのみ。C/D/Eの内容判断は実装していない。元の内部A〜Fの正式な意味はUNKNOWN。
- `comparison.json`：原本と候補の**実際の**バイト数、差分B、実測削減率。ゼロ削減も正確に報告。内部の手作業による圧縮率を自動機能の実績として転用しない。
- `self_test.json`：元ファイル不変、バックアップSHA、JSONとしての値一致、またはtextのバイト同一性など機械的な確認。**下書きだけから要点を再構成できるかという意味テストは`NOT_ASSESSABLE`**。人間・適切に権限を得たAIが別途審査する。
- `manifest.json`：生成ファイルのB数・SHA-256。同一性の証拠であり、内容が正しいことや意味の保存を証明しない。

生成された下書きを本来の常駐ファイルへ適用するCLIは**存在しない**。本人の明示承認があっても、この公開パイロット単体では適用できない。適用する場合は別工程の安全設計と承認が必要。

## 出力、終了コードと復旧

`stdout` JSONは各ターゲットの**安全な別名**、B数、文字数、行数、上限、前回比、週換算値、超過判定、結果SHAを示す。元のパスと中身は出さない。警告時は`package_id`と合計の比較値を返す。**状態・下書き・バックアップは実コンテンツを含むため公開禁止**。

- **exit 0:** `ok`または`warning`（どちらも測定成功）。警告が出た場合、下書き保存と履歴保存まで成功。
- **exit 1:** config/読み取り/UTF-8・JSON/履歴/パッケージ/書き込みの失敗。正確な合計なし。
- **exit 3:** ロック競合。実行せず停止。

未完の`.injection-temp-*`、history破損、状態の片方欠落、設定変更は自動再作成しない。本人がバックアップと履歴を精査して復旧を決める。原本は書き込まない。通常のMarkdown意味の圧縮・復元、他OS、非root権限拒否、大量/巨大ファイル、実環境性能、トークン単位コストは独立検証外。
