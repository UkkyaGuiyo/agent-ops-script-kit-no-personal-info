# 初心者へ：期限リマインダー係は何をするのか

仕事は「**確定した時刻が来たか**」を確認すること。AIに毎回「そろそろ？」と聞かず、日時という決まった条件を小さなプログラムに判定させる。

例えば架空の作業の期限が日本時間11:00なら、UTCの02:00、IANA地域名`Asia/Tokyo`、エポック秒が**同じ瞬間**を表すか確認してから登録する。3つが矛盾すれば何も進めない。時刻になって`check`を実行すると、一度だけ`fired`になり、通知すべき項目が私的なoutboxに`pending`として残る。

ここで重要なのは**発動と配送が別**だということ。期限が来たことは通知が届いたことを意味せず、届いたことも人間が読んだことを意味しない。繰り返し`check`しても同じ項目は再発動しない。外部の配送担当が失敗しても、同じpending IDを利用できる。ただし公開版自体は**一度も外部へ送らない**。`ack`は外部担当が渡した受領情報を**形だけ検査して記録する行為**で、実際の配送を確認・認証するものではない。

期限が取消になったら`cancelled`として履歴に残し、消さない。期限の変更は古い登録を取消し、新しい確定日時を新しいIDで登録する。時間表現の矛盾、履歴の破損、読み込み失敗はエラーであり、「リマインダーは0件だった」と読み替えない。outboxが壊れても正本ログが健全なら再構築可能だが、正本ログの破損は勝手に修理しない。

内部の本来の係には共通受け皿を使う配送と外部の見張りがあるが、この公開パイロットには入れない。案件専用の別方式である単発cronも実行しない。自動で毎朝動くことも、指定した分数以内に通知が届くことも、公開版の機能ではない。重要な予定の管理や外部通知は本人が承認した別の仕組みで行う。

**判断を行うのは人間または権限を持つ外部の担当者**。スクリプトは登録された確定期限を機械的に処理するだけ。時刻・保存・配送・閲覧の各段階を区別して説明できればよい。
