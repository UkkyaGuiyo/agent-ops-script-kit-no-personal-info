# 保持管理係を初心者へ説明する（C-7用）

この係は、「AIが不要だと思うファイルを選んで削除するもの」ではない。**ファイルを作った人が、作成時に `disposable`（使い捨て）か `permanent`（恒久）と宣言した記録**を見る。登録されていないものは探し回らない。

まず、整理係（第6号）が表示するのは「14日以上経った使い捨てファイルがある」という候補だけ。**候補は移動や削除の許可そのものではない**。保持管理係（第11号）は、その次の段階を見せる。ただし公開初版で実際に動かせるのは、**一時領域に自動生成した架空ファイルだけ**。

- **候補（preview）**：タグと更新時刻を調べて表示する。ファイルは変わらない。
- **ゴミ箱移動（stage）**：合成デモで`--apply`を明示した場合だけ、ゴミ箱内の日時付きフォルダへ移す。**まだ物理削除ではない**。
- **復元（restore）**：ゴミ箱に残ったファイルを、名前衝突がなく中身が一致すると確認できる場合だけ`--apply`で元へ戻す。安全を無条件に保証するものではなく、中断や破損時は停止する。
- **物理削除（purge）**：取り返せない工程。**公開版には存在しない**。内部版が約1か月後に削除するとの報告があっても、公開版が同じ削除をすることはない。

`permanent`は移動しない。区分が不明、記録だけありファイルがない、危険なパス、リンク類は保留。**正本が必要なファイルは、そもそも消せる区分にしない**。外部の正本に移したからといって、このプログラムが勝手にタグを反転することもない。

実際の運用で使うには、デモでは検証していない権限・障害復旧・競合・OS・保存先の事情がある。公開キットの`VERIFIED`/`PILOT`は、本番の削除権限の証明ではない。削除は不可逆で、別の明示承認と検証が必要。

## 新しいMuseが説明できるべきこと

1. 「消してよい」の宣言は**作成者が作成時にタグで行う**。AIが本文を読んで決めない。
2. 第6号は候補表示、第11号は**合成デモの移動・戻し**を示す。どちらも実データへの自動削除をしない。
3. 14日ちょうどで候補、少し手前は対象外。14日で物理削除するわけではない。
4. ゴミ箱は復旧可能な段階の例だが、**破損・衝突・停電などで戻せない場合もある**。
5. 物理削除は不可逆。公開版には`purge`も自動スケジュールもない。
6. `permanent`・未登録・不明区分は管理の対象にしないか保留。外部正本の存在を推測しない。
7. `--apply`の対象は専用に生成した架空デモ領域だけで、本番ファイルの許可ではない。
