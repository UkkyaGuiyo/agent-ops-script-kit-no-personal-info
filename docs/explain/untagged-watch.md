# 付け忘れ検出係を初心者へ説明する

**何をする係？** ファイルを作ったとき、「長く残す」「後で片付けてよい」という記録を付け忘れていないか、次の確認で見つける係。

**なぜこの係が必要？** 毎回AIがすべてのファイルを読み直す代わりに、小さなプログラムが新しいファイルと登録一覧を比べる。ファイルの**中身は読まない**。

**何が楽になる？** 新しいファイルの登録漏れを探す手間を減らせる。ただしトークン削減や速度向上は実測されていない。

**なぜ初回は知らせないの？** 導入前からあるファイルが大量に見つかって混乱しないように、初回は「今あるファイル」を覚えるだけだから。昔からあった未登録ファイルを見つける仕組みではない。

**何が危ない？** 調べる場所を間違えたり、権限が足りず調べられなかったりすると結果が欠ける。そういう場合は「何も無かった」と報告せず、エラーとして止まる。結果にはファイル名が載るため、公開しない。

**何を人間が決める？** どのフォルダを調べるか、報告されたファイルにどの区分を付けるか、状態が壊れたときにどう復旧するか。この係は区分を提案・設定せず、ファイルを削除しない。

**「pending」って？** 報告が保存されて、まだ受け取ったか確認していない状態。同じ報告がもう一度表示されることがある。受け取ったあとに確認操作（ack）をする仕組みで、外部サービスへの自動送信は付いていない。

**覚えておくこと：** 見張るファイルは読み取り専用。ただし前に見たファイルを覚えるために、別の保存場所には状態ファイルを作る。定期実行（6時間ごと等）はまだ設定しない。
