# 「整理係」を何も知らない人とAIに説明する

この係は、ファイルを種類ごとのフォルダへ片付けるプログラムではない。**ファイルの寿命を見張り、候補を示すもの**。

ファイルを作る人は、作成時に「使い捨て (`disposable`)」か「残す (`permanent`)」のタグを記録する。係はその宣言と、実際のファイルが最後に変更された日時だけを見る。中身を読んで「これは重要でない」と勝手に決めない。

例えば14日を基準にした場合、`disposable` のファイルが**最後の更新からちょうど14×24時間経過**していれば、ゴミ箱に移す**候補**になる。ただしこれはファイルを削除してよいという証明ではない。`permanent` は候補にならない。タグが無いファイルは調べず、分からないタグや存在しないファイルは「保留」にする。

## 公開版にできること・できないこと

- できる：登録済みファイルの更新時刻の確認と、**候補／未到来／対象外／保留**の一覧作成。
- できない：新しいタグを自動決定すること、フォルダ分け、ファイルをゴミ箱へ移すこと、物理削除、復元、スケジュール、自動通知。
- 停止条件：読み取り・設定の失敗、未知タグ・不正パスなどは無視せずエラー／保留として表示する。

元になった内部設計には、別操作でゴミ箱へ移動し、後でパージする機能が存在する。しかし**公開PILOTには存在しない**。初心者がREADMEを読んだだけでファイルが消えるようなことはさせない。

## よくある勘違い

**「14日で自動削除される？」** いいえ。候補を表示するだけ。

**「必要なファイルが消えるかどうかAIが判断する？」** いいえ。係は内容も他の正本も見ない。タグの正確さはファイルを作成・登録した人の責任。

**「未登録は『使い捨て』とみなされる？」** いいえ。対象外で、走査もしない。第3号の付け忘れ検出係は別の役割。

**「14日と1か月と90日は同じ保管期間？」** 違う。14日はこの係の候補閾値（変更可能）。1か月は内部版の別パージ操作に関する参考情報。90日は受け皿担当の別系統。混ぜない。

**「ドライランで大丈夫なら本番適用も安全？」** いいえ。この公開版に本番適用機能はない。提案は実行ではない。

テストは公開キットの**架空データ**で行う。実ファイル名・実パス・ローカル出力は公開しない。独立検証の状態は技術仕様を参照。
