# 共通受け皿を初心者へ説明する

**何をする係？** 色々な小さなプログラムが見つけたことを、一つの場所に集める係。郵便受けに似ているけれど、同じ手紙をもう一度入れても二重に並べない工夫がある。

**なぜ必要？** 拾い係ごとに報告場所が違うと、見落としや同じ通知の重複が起こりやすい。まとめた記録があればAIや人間が確認しやすい。

**何が楽になる？** 「何件まだ見ていないか」を旗で確認できる。担当のAIに一件ずつ探し回らせず、まとまった入口を用意できる。時間やトークンを何割減らせるかは測っていない。

**誰が判断する？** **受け皿は中身の意味を判定しない**。AIか人間が確認し、`unprocessed`（未処理）→`audited`（確認済み）→`reported`（報告済み）と進める。途中で`discarded`（取り扱わない）にする判断も受け皿の外で行う。

**なぜ記録を二種類に分けるの？** 到着・確認・報告の出来事は、消さずに追記するノートに残す。今の状況を一目で見るための旗は、そのノートから作り直せる。旗が壊れても、正しいノートが残っていれば復旧できる。

**保存したら送信元へ何と言う？** 「記録を保存できた」と返すのは、ノートへの書き込みと旗の更新が終わってから。途中で失敗したら成功とは言わない。同じ報告を再送しても、一件として数える。

**何が危ない？** 記録や結果には実際の作業情報が入ることがある。GitHubなどの公開場所に貼らない。ノートそのものが壊れていたら、自動で消したり作り直したりせず、人間に知らせる。取得が失敗した場合は「新着0件」とは違う。

**古い報告は勝手に消える？** **消えない**。未処理や確認済みの項目は削除候補からも除外する。報告済みなどの項目が一定期間を過ぎたとき、候補を**表示するだけ**で、今回の試作品は削除機能を持たない。90日は候補表示の初期値であり、保存期限の強制ではない。

**付け忘れ検出係とはどうつながる？** 付け忘れ検出係の「受け取ってほしい」という報告を、変換ツールでこの受け皿に登録できる。ただし実際に保存できた返答を確認するまでは、元の係の「送ったことにする」操作（ack）をしてはいけない。今回の版は手作業の例であり、自動配送は未搭載。

**初心者向けの注意：** 実際のアカウントやメールは不要。Pythonとローカルの架空データだけで試せる。実物のデータは公開しない。ほかの係へ勝手に操作権限を渡すものでもない。
