# 台帳係を初心者へ説明する

**どんな係？** 作業一覧の「書き方」を点検する小さなプログラム。たとえば作業名が重複している、決まった状態の言葉と違う、表の列が足りない、といったミスを知らせる。

**なぜAIに全部任せないの？** 決まった書式の確認なら、同じルールで繰り返し調べられるから。AIは結果を人に分かる言葉で説明する側に回る。

**何が楽になる？** 似た作業名の重複や、書式の抜けを自分の目だけで探す負担を減らせる。ただし処理速度やトークン節約の効果は実測していない。

**どこが危ない？** 書式が正しいからといって、本当に作業が完了したとは限らない。想定外の書き方なら見落としもありうる。参照先が見つからない場合と、権限のため確認できない場合は別々に知らせる。結果には作業名やローカルファイルの場所が含まれるので、公開しない。

**人間が決めること**：何を台帳に載せるか、異常をどう直すか、終わった項目を消す運用にするか。プログラムは勝手に削除・修正しない。

状態は **未投入 / 実行中 / 完了 / 本人保留** の四つだけ。「本人保留」は本人の再開指示待ちであり、自動的に催促する意味ではない。**合図待ち** は状態とは別の印。

**最初の一歩**：公開されている架空の台帳で試す。自身の台帳はローカルでのみ扱い、GitHubに載せない。
